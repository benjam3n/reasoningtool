# /aex The assumption that people will install a Claude Code plugin to get better thinking skills
**Date:** 2026-03-09
**Skill:** /aex (Assumption Extraction)

---

**Interpretation:** #1 -- Find hidden assumptions in a plan or argument. The input is a core strategic bet underlying the reasoningtool project: that people will install a Claude Code plugin to get access to better thinking skills. This is a plan/strategy analysis, so extraction focuses on Capability, Resources, Timing, Stability, plus Causal and Value.

**Depth:** 2x (default) -- minimum 8 assumptions, 3 layers deep, 3 categories, 2 hidden.

### CLAIM 2: A Claude Code plugin is an acceptable delivery mechanism

EXTRACTION QUESTIONS:

1. CAUSAL: What must cause what for this to work?
   -> Plugin installation must lead to skill discovery, which must lead to skill use, which must lead to perceived value.

2. EXISTENCE: What must exist that isn't proven?
   -> A large enough installed base of Claude Code users who also use plugins. Claude Code's plugin ecosystem must be robust enough that people are accustomed to installing plugins.

3. STABILITY: What must stay the same?
   -> Claude Code must continue to exist and support the plugin format. Anthropic must not deprecate or radically change the plugin API.

4. ACCESS: What must we be able to reach/use?
   -> The Claude Code plugin distribution channel must remain open. No gatekeeping that blocks the plugin.

5. CAPABILITY: What must someone be able to do?
   -> Users must be technically capable of installing a Claude Code plugin. This filters to developers or technical users.

6. VALUE: What must be considered good/desirable?
   -> The CLI/terminal must be considered a desirable interface for thinking work. Many people associate "thinking" with visual tools, whiteboards, documents -- not a terminal.

7. KNOWLEDGE: What must someone know?
   -> Users must know Claude Code exists, know it supports plugins, know this plugin exists, and know how to install it.

8. RESOURCES: What resources must be available?
   -> A Claude Code subscription (paid). This is a financial filter.

9. PERMISSION: What must we be allowed to do?
   -> Anthropic must permit this type of plugin in their ecosystem.

10. TIMING: What timing must be correct?

6. VALUE: What must be considered good/desirable?

7. KNOWLEDGE: What must someone know?
   -> How to use a terminal. How to install plugins. What the plugin does and why they'd want it.

8. RESOURCES: What resources must be available?
   -> Time to install and learn. Attention to discover it exists.

9. PERMISSION: What must we be allowed to do?
   -> N/A.

10. TIMING: What timing must be correct?
    -> Must catch people when they're in "tool-seeking" mode, not when they're heads-down on a project and resistant to new tools.

8. RESOURCES: What resources must be available?

9. PERMISSION: What must we be allowed to do?

## The Buried Insight

The deepest assumption here -- the one easiest to miss -- is **#4: people value the thinking process over fast answers**. The entire product bets that users will choose to invoke `/aex` and read through a structured extraction rather than just asking Claude "what are the assumptions in my plan?" and getting a decent freeform answer in 3 seconds.

The uncomfortable question: **is the delta between a skilled response and an unskilled response large enough to justify the overhead of installing a plugin, learning the skill taxonomy, and remembering to invoke specific commands?**

As models get smarter, this delta may shrink. The skills encode process knowledge that today's models sometimes miss -- but tomorrow's models may internalize. The moat, if there is one, is in the *curation and structure* of 592 skills, not in any single skill's output.

The second buried insight is the **discovery problem (#8)**. A solo developer with 592 skills and no distribution channel is like a library with no address. The assumption that "if you build it, they will come" is the most common and most lethal assumption in software.
